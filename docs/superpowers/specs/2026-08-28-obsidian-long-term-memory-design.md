# Obsidian 长期记忆系统设计

## 目标

将 `D:\obsidian` 作为 `nz news center` 项目的长期记忆库。Codex 在开始项目任务前检索相关笔记，在任务完成后仅回写对未来工作有价值的信息，包括项目背景、长期偏好、关键决策、已完成内容、当前进度、失败方案、踩坑记录、技术方案和下一步计划。

首期只接入以下项目：

- 项目目录：`C:\Users\harry\OneDrive\文档\nz news center`
- Obsidian 知识库：`D:\obsidian`

目录设计应允许未来增加其他项目，但本次不扫描或初始化其他项目。

## 架构

源码与长期记忆分离：项目仓库继续保存代码和项目内正式文档，Obsidian 保存跨任务使用的提炼信息。源码不会复制到知识库。

项目根目录使用 `AGENTS.md` 固化工作流程和知识库路径。该规则要求 Codex：

1. 开始任务前，根据任务主题检索项目记忆笔记。
2. 只读取完成当前任务所需的笔记，避免无关上下文。
3. 完成任务后，将新增且可复用的信息合并到对应笔记。
4. 更新当前状态、已完成内容和下一步计划时，移除已失效或重复的信息。
5. 不保存密码、API Key、Token、连接字符串、个人隐私或其他敏感信息。

## 知识库结构

```text
D:\obsidian
├─ 00-首页
│  └─ 长期记忆索引.md
├─ 10-项目
│  └─ nz-news-center
│     ├─ 项目总览.md
│     ├─ 当前状态.md
│     ├─ 关键决策.md
│     ├─ 技术方案.md
│     ├─ 已完成内容.md
│     ├─ 踩坑与失败方案.md
│     └─ 下一步计划.md
├─ 20-偏好
│  └─ 长期工作偏好.md
└─ 90-系统
   └─ 长期记忆维护规则.md
```

`长期记忆索引.md` 是入口页，链接到项目主页、长期偏好和维护规则。项目笔记之间使用 Obsidian 双向链接连接。

## 各文档职责

- `项目总览.md`：稳定的项目定位、目标、技术栈、核心目录和运行方式。
- `当前状态.md`：当前分支、正在推进的工作、已知阻塞和近期状态；保持简短。
- `关键决策.md`：记录重要决定、原因、替代方案和影响，使用带日期的条目。
- `技术方案.md`：记录仍然有效的架构、接口、数据流和实现约束。
- `已完成内容.md`：记录重要里程碑和已交付能力，不复制完整提交日志。
- `踩坑与失败方案.md`：记录失败表现、根因、无效尝试和以后应采用的做法。
- `下一步计划.md`：只保留尚未完成且仍然有价值的后续工作。
- `长期工作偏好.md`：保存跨任务稳定的协作和交付偏好，不保存一次性要求。
- `长期记忆维护规则.md`：定义筛选、更新、去重、安全和归档规则。

## 任务前检索流程

Codex 先读取 `长期记忆索引.md` 和该项目的 `项目总览.md`，再根据任务类型选择最多几个相关主题文档。例如，修复缺陷时优先查看 `当前状态.md`、`踩坑与失败方案.md` 和相关 `技术方案.md`；规划功能时优先查看 `关键决策.md`、`技术方案.md` 和 `下一步计划.md`。

Obsidian 内容作为辅助上下文，不替代对当前源码、测试结果和 Git 状态的检查。如果笔记与代码冲突，以可验证的当前仓库状态为准，并在任务结束后修正过时笔记。

## 任务后回写流程

任务结束时先判断信息是否满足至少一个条件：

- 会影响未来实现或决策。
- 能避免重复踩坑或重复调查。
- 描述重要的项目状态或里程碑变化。
- 是用户明确表达的长期偏好。

符合条件的信息合并到现有主题，而不是为每次对话创建新笔记。进度类内容应更新原条目，完成后从 `下一步计划.md` 移到 `已完成内容.md`。代码变更只保存结果、理由、关键文件和验证结论，不复制大段 diff。

## 初始内容来源

首次初始化从以下可信来源提炼：

- 项目 `README.md`。
- `docs/specs`、`docs/plans` 和其他现有项目文档。
- 当前 Git 状态和近期提交历史。
- 项目配置文件中可公开的技术栈信息。

初始化排除 `.env`、密钥文件、凭据、依赖目录、构建产物、缓存、临时文件以及与未来任务无关的聊天内容。任何疑似敏感值都不写入知识库。

## 失败处理与一致性

- 知识库不存在或暂时不可访问时，Codex继续完成项目任务，并明确说明本次未同步记忆。
- 笔记缺失时按既定结构创建；笔记格式异常时保留原内容并做最小修复。
- 写入前检查重复内容，避免同一决定散落在多个文件。
- 不自动删除具有历史价值的决策或踩坑记录；过时内容标记为已取代并链接到新决定。

## 验证标准

实施完成后应验证：

1. `D:\obsidian` 中的目录和 Markdown 文件可被 Obsidian正常显示。
2. 首页可以链接到项目和维护规则，项目文档之间的链接有效。
3. 项目根目录规则明确包含任务前检索、任务后回写和敏感信息禁写要求。
4. 初始笔记内容能追溯到当前项目文件或 Git 历史，没有凭据和无关临时内容。
5. 模拟一次任务前检索和任务后更新，确认流程清晰且不会产生重复笔记。
